# astro-md-translate

AI translation for Astro / Markdown-driven sites and i18n JSON language files — with format protection built in: fenced code, inline code, link URLs, images, HTML tags, interpolation placeholders and brand terms all survive translation untouched.

## Install

```sh
pnpm add -D astro-md-translate
# or run without installing:
npx astro-md-translate --help
```

## Quick start

```sh
# 1. Generate a ready-to-use config, glossary and dictionary
npx astro-md-translate init

# 2. Edit astro-md-translate.config.json:
#    set provider fields (apiUrl / apiKey / model) and targetLocales

# 3. Preview, then translate
npx astro-md-translate translate-md --dry-run
npx astro-md-translate translate-md
npx astro-md-translate translate-json --locales zh-CN
```

Minimal config (all fields are optional; this shows the ones you usually change):

```json
{
  "apiUrl": "https://example.com/v1/chat/completions",
  "apiKey": "YOUR_API_KEY",
  "model": "example-model",
  "sourceLang": "en",
  "targetLocales": ["zh-CN", "es"]
}
```

`apiUrl` 指向 OpenAI 兼容的任意 endpoint，上面的地址仅为示例占位 — replace it with your provider's URL.

## Output model

- **Source files are never modified.** Markdown translations are written to `<cwd>/<locale>/<relative path>` (e.g. `en/docs/guide.md` → `es/docs/guide.md`). JSON translations are written as `<locale>.json` next to the source (`en.json` → `es.json`).
- Existing translations are overwritten on re-translation (normal behaviour).
- If validation fails for a file, it is **not** written — the previous translation (if any) is kept and the error is recorded; other files continue.
- 0.1.0 does not provide an in-place overwrite switch. If you need one, apply it with a downstream script.

## Markdown protection list

- **Fenced code blocks** — never parsed as text, kept verbatim.
- **Inline code** — kept verbatim.
- **Link URLs** — link targets are never modified.
- **Image paths** — image targets are never modified.
- **Image alt text** — the alt of `![alt](/path)` and `![alt][ref]` **is translated**; the path, the reference identifier (`[ref]`) and the `title` attribute are not. An alt that exactly matches a glossary `protected` term is kept as-is (no provider call).
- **HTML tags and attributes** — masked and restored (e.g. `<br/>`).
- **Frontmatter** — only fields listed in `md.translatableFields` are translated; `md.reservedKeys` (e.g. `slug`, `date`) are never touched.
- **GitHub alerts** — `[!NOTE]` and similar markers pass through as-is.
- **Interpolation placeholders** — `{name}`, `{{count}}`, `${x}`, `%s` (configurable via `json.placeholderPatterns`) are masked in body text and restored verbatim.
- **Glossary protected terms** — masked during translation and restored (optionally to their `replacement`, e.g. a ® form).

## i18n JSON protection list

- **Keys are never translated** — only string values; key set, nesting and array order are preserved.
- **Placeholders keep their names and counts** — verified after translation; a count change is an error.
- **Key blacklist** — `id`, `slug`, `url`, `icon` (and more, see `json.keyBlacklist`) are never translated.
- **Empty strings, numbers and symbol-only values** (`---`, `***`) are kept as-is.
- **ICU `plural` / `select` skeletons are not protected in 0.1.0** — `check` reports them as a warning.

## Glossary and dictionary

`glossary.yaml` (generated by `init`, edit freely):

```yaml
entries:
  - term: ExampleBrand
    replacement: ExampleBrand®
    protected: true      # masked during translation, restored to `replacement`
  - term: SampleTerm
    preferred: SampleTermTranslation
    protected: false     # translated normally, `preferred` guides the model
```

`dictionary.json` short-circuits the provider for common words — exact (or case-insensitive) source matches are replaced locally without an API call.

## CI (GitHub Actions, PR mode)

Run translations on a schedule or push, then open a pull request instead of pushing to `main` directly:

```yaml
# .github/workflows/translate.yml
name: translate
on:
  workflow_dispatch:
  schedule:
    - cron: "0 3 * * 1"
permissions:
  contents: write
  pull-requests: write
jobs:
  translate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: pnpm
      - run: pnpm install --frozen-lockfile
      - name: Translate Markdown and JSON
        env:
          API_KEY: ${{ secrets.TRANSLATION_API_KEY }}
        run: |
          npx astro-md-translate translate-md --changed-only
          npx astro-md-translate translate-json --changed-only
      - name: Open PR with new translations
        uses: peter-evans/create-pull-request@v6
        with:
          branch: translations/batch
          title: "chore: update translations"
      - name: Smoke check with the mock provider (no API calls)
        run: npx astro-md-translate check
```

Details (secrets setup, why PR mode, `--changed-only` in CI): see [docs/ci.md](docs/ci.md).

## `--dry-run` output and exit codes

```text
sample.md  →  es/sample.md (×2)  segments=13  code=1  inline=2  url=3  placeholder=4  glossary=2
Summary: files=1 willTranslate=1 skipped=0 code=1 inline=2 url=3 placeholder=4 glossary=2 locales=2
```

Each line shows: source path, output path (first locale + locale count), translatable segment count and per-protection hit counts. `--verbose` expands to segment level (segment index + hit protection types, no content). The trailing `Summary:` line aggregates everything.

| Exit code | Meaning |
| --- | --- |
| `0` | Success (including `--dry-run`, and `check` with no `error`-level issues) |
| `1` | Invalid parameters, invalid config, or `init` target exists without `--force` |
| `2` | Translation or validation failure, or `check` found `error`-level issues |

Warnings (`warn`) never change the exit code.

## Known limitations

- Anchor validation (`md.anchor-broken`) is heuristic — a warning only; the downstream framework build is the final authority.
- Markdown image alt text (`![alt](/path)`) **is** translated; HTML `<img alt="…">` alt and frontmatter image fields are **not** translated.
- ICU plural/select skeletons are not protected — `check` warns; review manually or blacklist the key.
- No segment-level cache — a changed file is fully re-translated and consumes API quota again.
- One default provider implementation: `HttpTranslator` (OpenAI-compatible chat-completions endpoint).
